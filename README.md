# 宿舍用电小账本（dorm-power）

一个给自己宿舍用的**用电余量预警服务**：按周录入电表读数，用日均外推余量与预计断电日，到阈值通过微信推送提醒。

线上运行：`https://dorm-power-ledger.app.workbuddy.host/`（分享链接需带 `sharecode`）

---

## 为什么做这个

学校缴费平台只覆盖 1–9 号楼，本楼（19 号楼）查不到余量；宿管每周手工抄表一次，学生只能等断电才知道。

- 电控系统没有对外接口，个人拿不到；
- 宿舍禁止加装电表 / 私改电路；
- 缴费必须去卡务中心，周末不办。

所以**放弃"实时监控"**，改为「人工录入 + 日均外推」——数据源只有每周一次的人工读数，那就把这一条数据用到极致。

## 核心计算

```
日均         = (最早读数 − 最近读数) ÷ 相隔天数
估算余量     = 最近读数 − 日均 × 距最近读数天数
预计可用天数 = 估算余量 ÷ 日均
预计断电日   = 今天 + 预计可用天数
```

阈值不是拍脑袋定的：学校会把低于 **100 度** 的房间贴在公告处，充值要跑卡务中心且周末不办 → 取 `日均 × 7 天`（当前 **120 度**），比校方提醒提前约 2.5 天。

## 功能

| 能力 | 说明 |
|---|---|
| 双权限 | 管理员（明细 + 全部操作）／访客（取整概览，只读） |
| 服务端裁剪 | 访客响应里不含 `records` 字段，越权写接口返回 403 |
| 事件日志 | 登录 / 录入 / 删除 / 改设置 / 推送结果，保留 300 条 |
| 数据导出 | CSV（Excel 对账）、JSON（迁移与恢复） |
| 数据保护 | 每日快照 `.bak` + 启动自检恢复 |
| 定时推送 | 每晚 23:55，含 30 分钟补发窗口与外部 cron 兜底 |
| 开放接口 | `GET /api/open/summary`，独立 token、60 次/分限流、只读 |
| 录入校验 | 同日重复录入拦截；偏离历史日均 >40% 需二次确认 |

## 技术栈

- 后端：Node.js 原生 `http`，**零第三方依赖**
- 前端：单文件 HTML（内联 CSS/JS），无构建
- 存储：`data.json` + 原子重命名写入
- 部署：单端口 HTTP 服务（托管容器），零服务器成本
- 推送：PushPlus（微信）

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/` | — | 页面（内嵌首屏数据 + gzip） |
| GET | `/api/state` | — | 按身份返回 owner / guest / setup |
| POST | `/api/login` | — | 管理员登录 / 首次设口令 |
| POST | `/api/reading` | 管理员 | 记读数（支持 `date` 补录） |
| POST | `/api/charge` | 管理员 | 记充值（仅记账，不计入余额） |
| DELETE | `/api/record/:id` | 管理员 | 删除记录 |
| POST | `/api/settings` | 管理员 | 房间号 / 阈值 / 人数 / token |
| GET | `/api/export` | 管理员 | 导出 CSV / JSON |
| GET | `/api/open/summary` | openToken | 只读概要（供 LLM / 外部系统） |
| GET | `/api/cron` | cronSecret | 外部定时触发推送 |

## 本地运行

```bash
node server.js          # 默认 3000 端口
# 浏览器打开 http://localhost:3000
```

首次访问会要求设置管理口令；数据写入同目录 `data.json`（已在 `.gitignore` 中，不会入库）。

## 已知边界

- 数据粒度 7 天，**不支持实时采集**（数据源不存在）；
- 单实例、单租户，无并发写入保护（估算 10 万条记录后才需要换 SQLite）；
- 口令以明文存于 `data.json`，未做哈希（内部工具场景的取舍）。
